# Explosive 420 live link: owner runbook

Puts Explosive 420 Cannabis Social Club on **https://explosive420.web.app**. It uses the
production Supabase project that 224 uses, with tenant `explosive420`. Every flow is on:
sign-up, cart, checkout (cash or card on delivery), orders, membership, newsletter,
reservations and reviews. EFT is hidden because the store has no bank details yet.

Prepared and checked on the local stack on branch `demo/explosive420`. **You** run every
command below. Run them from the repo root, on that branch, in this order.

## 0. Account checks (CLAUDE.md, every time)

```bash
gh auth status              # tlaphane-1
firebase login:list         # tlaphane@gmail.com
supabase projects list      # 224 Clubhouse project aogdkqczvlffgydgxsmz is linked
```

Stop if any of these is wrong.

## 1. Supabase Auth redirect allow-list (dashboard, one time)

Go to Dashboard → Authentication → URL Configuration → **Redirect URLs** and add:

```
https://explosive420.web.app/**
```

Leave the Site URL as `https://224clubhouse.store`.

**Why:** sign-up confirmation and password-reset links send people back to the page they
came from (`window.location.origin` + path). Supabase only honours a redirect that is on
this list. Without it, an Explosive 420 customer who confirms their email lands on
**224clubhouse.store**, signed in, and sees Explosive 420's catalogue in 224's branding.
The local stack showed this fallback: a reset requested from `localhost:5420` came back
with `redirect_to` set to the local Site URL.

**Undo:** remove the entry.

## 2. Create the hosting site

```bash
firebase hosting:sites:create explosive420
```

This adds a second Hosting site, `explosive420`, to project `clubhouse-61730`. It does not
touch 224's site.

- **Verify:** `firebase hosting:sites:list` shows `explosive420`.
- **Undo:** `firebase hosting:sites:delete explosive420`. This also deletes everything
  deployed to it.

## 3. Provision the store's data

Dry run first. It prints the plan and writes nothing:

```bash
node scripts/provision-explosive420.mjs --production --admin
```

Then apply it:

```bash
node scripts/provision-explosive420.mjs --production --admin --yes
```

What it writes. Every row carries tenant `explosive420`, and nothing of 224's is changed:

| Where | What |
|---|---|
| `tenants` | The `explosive420` row: order prefix `E420`, min age 21 |
| `alert_settings` | An empty row for the store. Telegram stays off. |
| `products` | 8 products, each with stock 50. A re-run never resets stock. |
| `membership_tiers` | "Monthly Membership", R100, 30 days |
| Storage | `tenants/explosive420/assets/*` uploaded to `brand-assets/e420/` |
| `--admin` | Auth user `tlaphane+explosive420@gmail.com` (email confirmed, tenant claim `explosive420`) and its `admin_users` row |

- The admin password is generated by the script and never printed. It is written to
  `scripts/explosive420-admin.local`, which is gitignored.
- If the admin already exists, the script leaves the password alone. It refuses to
  continue if that account belongs to another store.

The script refuses to run unless `.env.local` points at `aogdkqczvlffgydgxsmz.supabase.co`.
It ends with a check using the anon key:

- With `x-tenant: explosive420`, it must see the 8 products and the tier.
- With no header (224's view), it must see **0** Explosive 420 products.

It prints `verify: PASS` when both hold.

**Change the admin password after the first sign-in.** Sign in at
`https://explosive420.web.app/admin/login`, open `https://explosive420.web.app/reset-password`
while signed in, and set a new password. Once step 1 is done, "Forgot password" on the
admin login page also works.

**Undo:**

```bash
node scripts/provision-explosive420.mjs --production --remove --admin --yes
```

This deletes everything the script made:

- the admin's `admin_users` row and its auth user
- the products and variants, the tier and the `alert_settings` row
- the storage objects under `brand-assets/e420/`, `product-images/e420/` and `event-images/e420/`

It deletes the `tenants` row only if nothing else references it. If customers have used the
store, it lists what is left (orders, memberships, profiles and so on). To clear those first,
run this in the SQL editor:

```sql
-- Explosive 420 customer data only. Check the counts before deleting.
delete from product_reviews       where tenant = 'explosive420';
delete from event_reservations    where tenant = 'explosive420';
delete from events                where tenant = 'explosive420';
delete from memberships           where tenant = 'explosive420';
delete from orders                where tenant = 'explosive420';
delete from saved_carts           where tenant = 'explosive420';
delete from newsletter_subscribers where tenant = 'explosive420';
delete from contact_messages      where tenant = 'explosive420';
delete from site_events           where tenant = 'explosive420';
delete from customer_email_prefs  where tenant = 'explosive420';
delete from customer_profiles     where tenant = 'explosive420';
-- Explosive 420 sign-ups (their claim names the store; 224 accounts all say 224clubhouse):
delete from auth.users where raw_app_meta_data->>'tenant' = 'explosive420';
```

Then re-run the `--remove` command.

`tenants.active = false` is not an off switch: nothing reads it yet. To take the store
offline quickly, use the hosting step 5 undo instead.

## 4. Build

```bash
npm run build:e420
```

This runs `scripts/build-store.mjs explosive420`. It builds with `TENANT=explosive420` into
`dist-explosive420/` and prerenders the SEO pages there. 224's `dist/` is never touched.

It blanks four of 224's own `.env.local` values so they cannot reach this store:

- the WhatsApp order number
- the EFT bank details
- the Paystack key
- the Maps key

**Verify:**

- The build prints `wrote 8 static, 8 product … pages`.
- `dist-explosive420/index.html` has the title `Explosive 420 Cannabis Social Club | Soshanguve`.
- `dist-explosive420/store/` holds the 8 Explosive 420 product pages.

## 5. Deploy

```bash
firebase deploy --config firebase.explosive420.json --only hosting
```

`firebase.explosive420.json` is a copy of `firebase.json` with the same headers and rewrites.
It has `"site": "explosive420"` and `"public": "dist-explosive420"`. 224's `firebase.json` and
`.firebaserc` are unchanged, and a plain `firebase deploy` still deploys only 224.

**Verify on a phone:** open https://explosive420.web.app and check that:

- the age gate says 21
- there is no reviews section and no 224 copy
- checkout offers cash or card on delivery only

**Undo:**

- Roll back in Firebase console → Hosting → explosive420 → release history.
- Or take it down with `firebase hosting:disable --site explosive420`.

## What Explosive 420 customers get from the server today (not yet store-aware)

These run on production for every store. Nothing in this branch changes them.

- **Auth emails** come from the dashboard templates, which are 224-branded. That covers sign-up
  confirmation ("Confirm your 224 Clubhouse account") and reset ("Reset your 224 Clubhouse
  password"). The email says "224 Clubhouse", shows 224's logo and address, and comes from
  224's sender. The link lands on Explosive 420 only after step 1.
- **Edge Functions:**
  - `send-order-email`, `send-status-email`, `send-membership-email`,
    `send-membership-application-alert`, `send-payment-email`, `send-review-alert` and
    `send-welcome-email` all send 224-branded mail. They come from `…@224clubhouse.co.za`,
    link to `224clubhouse.store`, and show 224's address and socials.
  - Owner alerts (new order, new membership application, review waiting) go to
    **224's `ADMIN_ALERT_EMAIL`**.
  - Order, membership, review and delivery Telegram alerts read 224's `alert_settings`,
    because the service role sends no header. So if Telegram is ever switched on for 224,
    **Explosive 420 orders would post to 224's group**.
  - The welcome email offers `WELCOME10`, which is 224's code. It does not work at
    Explosive 420's checkout because codes are per store. The site's newsletter copy for
    Explosive 420 therefore promises no discount.
  - The daily summary and cart reminders cover 224 only, so Explosive 420 gets neither.
- **Telegram** is hidden on Explosive 420's admin (`"telegram": false`), so its admin can never
  call `telegram-connect` and overwrite 224's bot token (Ruling 16).
